# 原型：情绪是否真的改变了行为

这个目录只验证一件事：**评价 → 情绪 → 6 个决策旋钮**的链路是否成立，以及情绪有没有层次、有没有记忆。
它不调用任何模型，评价是手写的（`scenarios.py`），所以跑起来是秒级的、完全可复现的。

## 怎么跑

双击 `run.cmd`，或者在终端里：

```
cd D:\fish-memory\prototype
py -3 -X utf8 run.py
```

`run.cmd` 会自动找 `py -3` → `python` → 内置解释器。`exit code: 0` 表示判定全过。

## 看什么

四组剧本，每组一张表：

| 列 | 含义 |
|---|---|
| `v` / `a` | 效价 / 唤醒度 |
| `guilt` | 未修复的愧疚，**不随时间衰减** |
| `verb` `refu` `veri` `risk` `disc` `pati` | 6 个决策旋钮，0.5 是基线 |

重点看第三组（违背承诺后六轮平静）：`v` 从 −1.00 回到 −0.38，`pati` 从 0.06 回到 0.40，
但 `veri` 停在 0.78 不动。**情绪平复了，但没翻篇。**

## 怎么改

| 想试什么 | 改哪里 |
|---|---|
| 清醒节律（每小时 / 每3小时 / 随机区间） | `config.json` → `wake.interval` |
| 主动联系配额、间隔、时段 | `config.json` → `contact` |
| 某一类事件的严重程度 | `scenarios.py` 里的数值 |
| 情绪衰减快慢、反应强度 | `engine.py` 里的 `Temperament` 与权重 |
| 判定阈值 | `run.py` 末尾的 `check(...)` |

改完直接重跑，不用编译。

## 判定 FAIL 了怎么办

先别当成 bug。`run.py` 里的断言是**设计意图**，不是正确性检查：

- 你调低了某个事件的严重程度 → 「耐心显著下降」可能就不成立了，那是预期的
- 你调快了衰减 → 「情绪已平复」会更容易过
- 真删掉了持久项 → 「死区不吞掉持久项」会失败，那才是 bug

判定失败时它会给出现值，和阈值对比一眼能看出来是设计变了还是实现错了。

## 文件

```
config.json    节律与联系配额
engine.py      评价 → 情绪 → 旋钮（纯计算，无 I/O）
scheduler.py   什么时候醒
contact.py     什么时候可以主动联系
scenarios.py   剧本里的评价数值
run.py         跑四组剧本 + 断言
```

## 它没证明的事

这 6 个数确实在变，但**没有证明它们能改变模型的输出**。那需要接真模型做 A/B：
同一段对话，`bias` 固定 0.5 的对照组 vs 真实 `bias` 的实验组，然后盲评。
如果盲评分不出来，问题在评价器，不在加更多机制。
