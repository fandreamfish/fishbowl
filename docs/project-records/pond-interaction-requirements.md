# 鱼塘设置页与鱼间交流需求

状态：需求澄清中。本文补充 requirements.md，不代表实现方案已批准。

## 用户原始要求

> 这个鱼塘程序应该有一个设置页面，可以设置每条鱼的状态，还有如果开启了2条鱼，那么这两个鱼可以设置 视觉范围， 可以看到其他的鱼，可以和其他的鱼进行对话交流

## 已提出的需求

- 独立鱼塘程序提供设置页面。
- 可以分别设置每条鱼的状态。
- 支持同时开启多条鱼，至少覆盖两条鱼同时开启的情况。
- 可以设置鱼的视觉范围。
- 在允许的范围内，鱼可以看到其他鱼。
- 鱼可以与其他鱼对话交流。
- 本功能继续遵守项目已有审计和状态归属要求。

## 已确认的视觉范围与其他待确认概念

### 视觉范围（已确认：可见对象名单）

用户选择视觉范围方案 1：按每条鱼配置能够看到哪些其他鱼，不要求二维位置、移动或视野距离。

例如鱼 A 的可见名单可以包含 B、C，不包含 D。

视觉范围与记忆访问是两项独立设置。后续用户已确认记忆方案 1：每条鱼可召回自己跨 DSH、QQ 等渠道的全部记忆，不能直接读取其他鱼的记忆。详见 `connection-session-rules.md`。

还需确认单向/双向可见、能否看到状态和公共对话、以及看不到时能否交流。

### 每条鱼的状态

需区分运行设置与个体内在状态：

- 运行设置候选：启用、暂停、模型、作息、交流开关、可见对象、调用预算。
- 内在状态候选：情绪、关系、记忆和人格倾向。

手动修改内在状态是否允许尚未确认；若允许，需要记录为可追溯的管理事件，明确是否影响账本重放。

### 交流机制

尚未决定交流由用户触发、鱼主动触发，还是两者都支持。

待确定：私聊或公共场所、回合调度、终止条件、配额、是否允许旁观和用户介入。

## 设计建议（未批准）

- 区分管理员全局视角和每条鱼自己的感知范围。
- 可见不代表能读取对方私密记忆、完整账本或用户私聊。
- 每条鱼维持独立身份、记忆和情绪；收到鱼间消息时标记真实发送者。
- 对话内容只能作为交流输入，不能成为修改对方权限或设置的管理指令。
- 设置变更、感知信息交付、对话发起、消息投递和终止都应可审计。
- 自动交流需要回合、时间或调用预算上限，以避免无限互相唤醒。
- 通信与状态协调由 Fish Runtime 负责；不要求经由 DSH。
