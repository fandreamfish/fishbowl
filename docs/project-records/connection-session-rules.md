# Fish 接入、会话与消息规则

状态：需求澄清中。补充 requirements.md；以用户明确要求为准，不替代原始讨论档案。

## 本轮用户明确要求

- 单个 Fish 首期只允许一个 DSH 接入，后期可能扩展多个。
- 允许 DSH、QQ 等不同类型远程程序连接同一个体；每种类型当前只能接一个。
- 同一个体收到多条消息时排队处理。
- 一个 DSH 会话只允许连接一条鱼。
- 鱼可以看到全局记忆。

## 规则整理

### 接入数量

按“每条鱼 × 远程程序类型”限制接入数量：每条鱼最多一个 DSH 接入、一个 QQ 接入；不同类型允许同时接入。

这是基于本轮上下文的理解。连接数、程序实例数和会话数是不同概念；一个 QQ 接入是否允许包含多个聊天对象、一个 DSH 插件是否可服务不同鱼的多个会话，尚未确认。

同一条鱼首期不能同时绑定多个 DSH 会话；每个 DSH 会话也不能同时绑定多条鱼。后续可能放宽前一项限制。

### 消息处理

同一条鱼的消息排队处理，不默认打断当前回合，不并行执行多个回合。

建议（待确认）：来自 DSH、QQ 和鱼间交流的消息进入该鱼统一队列，按 Fish 接收并入队的顺序执行；不同鱼可独立调度。

排队长度、等待超时、取消、服务重启后的恢复和后台任务排序尚未确定。

### 会话绑定

一个 DSH 会话只允许连接一条鱼。

该约束不等同于“新建 DSH 会话自动新建鱼”。新会话是否手动选鱼、自动出生，或恢复既有绑定，仍待确认。

### 全局记忆（已确认：方案 1）

用户确认：全局记忆指该鱼自己跨 DSH、QQ 等所有入口的全部记忆，不是鱼塘中所有鱼的记忆。

- 同一条鱼的记忆不按接入渠道彼此隔离，可跨渠道召回自身经历。
- 不允许仅凭可见关系直接读取其他鱼的记忆。
- 视觉范围决定可见对象，不改变记忆的个体归属。
- 跨渠道可召回不代表向所有聊天对象自动披露全部记忆；回复中的披露规则尚待确认。

## 接入可靠性待确认

- 断线期间是否保留会话绑定和未投递回复？
- 接入绑定、替换、入队、执行和结果投递均需遵循已有审计要求。
