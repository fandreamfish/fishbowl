# Fishbowl 待确认问题清单

状态：需求澄清中。这里保留历史待确认问题。最新确认以 confirmed-social-and-runtime-rules.md 为准：记忆披露、主动多轮社交、双向可见、独立每日预算、旁观插话、管理员运行设置和串行优先队列已确认；具体限额、断线默认策略等仍待细化。DSH 调查见 dsh-feasibility.md。

## P0：进入开发前必须确认

### 1. DSH 对话替代闭环

- 插件能否在模型请求前捕获用户消息。
- 能否阻止本轮 DSH 模型调用。
- Fishbowl 回复能否作为合法 assistant 输出回到原会话。
- DSH UI 能否展示该回复并保持历史一致。
- Fishbowl 工具循环期间，DSH 如何提供取消、状态和结果。

### 2. 记忆披露

已确认：每条鱼可以召回自己跨 DSH、QQ 等入口的全部记忆，不能直接读取其他鱼的记忆。

仍需确认：鱼在与人、其他鱼、群聊交流时，是否允许自动说出自己的全部记忆。建议区分“模型可检索”与“可向当前对象披露”，增加披露策略和敏感记忆过滤。

### 3. 鱼间交流的触发方式

- 只允许用户触发。
- 允许鱼主动发起。
- 两者都允许。

还需确定：交流是否需要双方都在对方可见名单中；可见是单向还是必须双向；消息是否进入双方各自记忆。

### 4. 会话和个体生命周期

- 新建 DSH 会话如何绑定鱼：手动选择、自动新建或恢复绑定。
- DSH 会话关闭后是否保留绑定。
- 鱼暂停/删除/封存时，已有接入如何处理。
- 同类第二个远程接入：拒绝、等待还是管理员替换。

### 5. 消息队列语义

已确认同一个体的消息排队。

仍需确定：队列最大长度、超时、优先级、取消、重启恢复、鱼间消息与用户消息的优先级，以及一条消息失败后是否阻塞后续消息。

## P1：首期设计时确认

### 6. 设置页权限

- 谁可以设置鱼的启用、暂停、模型、可见名单和交流权限。
- 状态编辑是管理员操作还是鱼自己可操作。
- 修改情绪/记忆/人格是否允许；若允许是否以事件形式写入账本。
- 设置变更是否需要二次确认。

### 7. 可见范围的具体内容

已确认视觉范围是可见对象名单，不使用空间位置。

仍需确定看到对方时能看到：名称、运行状态、情绪摘要、正在做什么、公开消息，还是完整状态摘要。建议默认不提供私密记忆、用户私聊和敏感配置。

### 8. 鱼间对话模型

- 一次交流是一条消息还是完整会话。
- 是否允许连续多轮。
- 最大轮数、预算和终止条件。
- 用户是否可以旁观、插话、暂停或终止。
- 鱼间交流是否产生独立会话和审计 trace。

### 9. 模型与成本

- 每条鱼是否可以选择不同 Model Provider。
- 每轮模型调用上限、Token 预算和费用上限。
- 工具调用和主动交流是否独立计费。
- 达到预算后返回、排队还是停止。

### 10. 审计的隐私和留存

- 审计保存多久。
- 是否保存完整消息，还是只保存摘要/哈希。
- 哪些管理员可以查询审计。
- 审计导出是否需要脱敏。
- 审计存储是否需要哈希链或外部只读归档。

### 11. 失败和降级

- Fish 不在线时 DSH 是否回退自己的模型。
- DSH 断开时 Fish 是否继续完成当前回合。
- 模型失败是否重试。
- 工具结果未知时是否允许重试。
- 用户取消后已完成外部操作如何标记。

## P2：后续增强

### 12. 多 DSH/多实例

当前每条鱼每类程序最多一个接入，后期可能允许一条鱼多个 DSH 会话。需要届时定义消息排序、会话隔离、冲突和资源配额。

### 13. 共享记忆区

当前不共享其他鱼的私有记忆。未来如需要鱼塘公共记忆，应单独建共享记忆区，不能直接打破个体记忆隔离。

### 14. 高级鱼塘行为

包括主动社交、群体事件、鱼塘广播、鱼之间的关系网络、公共场景和长期社会记忆。
