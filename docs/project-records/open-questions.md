## P0：进入开发前必须确认

### 1. DSH 任务闭环的实际 API 验证

替代模型闭环已退出首期。需实测：任务提交和接收确认、绑定会话与任务 ID 关联、最终完成识别、取消及重启恢复。规则已确认，DSH API 能否实现仍待验证；协议 Schema、具体超时/保留值及认证机制待设计。

最新证据见 dsh-task-validation.md：CLI rc.2 的真实内核探针已通过五个场景，桌面 rc.5 源码已核对；桌面插件、真实模型及协议持久恢复仍待验证。needs_input 行为已确认，结构化输出如何可靠生成/校验仍待设计。

接口设计已有待评审草案 task-protocol-design.md 和 dsh-control-state-machine.md，提出最终 JSON 结果体、配对认证、消息信封及具体限额。这里的“待设计”已有候选答案，尚未冻结；尤其需验证桌面会话排他/人工插入检测、取消检查与执行的同步保证、崩溃后 inbox/session 核对。若缺少这些能力，不能仅凭协议设计宣称完整闭环可用。

### 2. 记忆披露

已确认：每条鱼可以召回自己跨 DSH、QQ 等入口的全部记忆，不能直接读取其他鱼的记忆。

已确认检索与披露分开，默认不向其他对象自动公开私密记忆。待设计具体分类、过滤与授权配置。DSH 结果记忆必须标注来源及结果状态。

### 3. 鱼间交流的触发方式

已确认允许主动发起、双方互相可见、多轮交流，内容进入各自记忆。每日次数/消息数和 Token 预算的计量、重置与结束细节待设计。

### 4. 会话和个体生命周期

- 新建 DSH 会话如何绑定鱼：手动选择、自动新建或恢复绑定。
- DSH 会话关闭后是否保留绑定。
- 鱼暂停/删除/封存时，已有接入如何处理。
- 同类第二个远程接入：拒绝、等待还是管理员替换。

### 5. 消息队列语义

已确认同一个体的消息排队。

已确认同鱼消息串行、用户消息优先于鱼间消息、单条失败不阻塞后续。DSH 异步任务等待不占消息队列，结果作为独立事件入队。待设计队列上限、具体超时、背压和防饥饿机制。

## P1：首期设计时确认

### 6. 设置页权限

已确认运行配置由管理员设置，默认不直接修改情绪、记忆、人格；若允许修正必须使用可审计事件。管理员登录与身份模型、敏感配置变更确认机制待设计。

### 7. 可见范围的具体内容

已确认视觉范围是可见对象名单，不使用空间位置。

仍需确定看到对方时能看到：名称、运行状态、情绪摘要、正在做什么、公开消息，还是完整状态摘要。建议默认不提供私密记忆、用户私聊和敏感配置。

### 8. 鱼间对话模型

已确认允许多轮、独立预算、用户旁观和插话。仍待明确轮数、预算细节、终止条件、用户暂停/结束权限和社交会话组织。

### 9. 模型与成本

- 每条鱼是否可以选择不同 Model Provider。
- 每轮模型调用上限、Token 预算和费用上限。
- 工具调用和主动交流是否独立计费。
- 达到预算后返回、排队还是停止。

### 10. 审计的隐私和留存

- 审计保存多久。
- 是否保存完整消息，还是只保存摘要/哈希。
- 哪些管理员可以查询审计。
- 审计导出是否需要脱敏。
- 审计存储是否需要哈希链或外部只读归档。

### 11. 失败和降级

已确认 DSH 已接收任务由 DSH 掌控，断线/超时不等于任务停止；重连查询/补投最终结果，未知副作用不盲重跑，取消必须由 DSH 确认且不能撤销已完成操作。任务、去重和通知状态需持久化。待设计具体重试上限、记录保留周期和端点不可用时的提示。

## P2：后续增强

### 12. 多 DSH/多实例

当前每条鱼每类程序最多一个接入，后期可能允许一条鱼多个 DSH 会话。需要届时定义消息排序、会话隔离、冲突和资源配额。

### 13. 共享记忆区

当前不共享其他鱼的私有记忆。未来如需要鱼塘公共记忆，应单独建共享记忆区，不能直接打破个体记忆隔离。

### 14. 高级鱼塘行为

包括主动社交、群体事件、鱼塘广播、鱼之间的关系网络、公共场景和长期社会记忆。
