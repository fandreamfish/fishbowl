# fishbowl 记忆系统设计

> 状态：**定稿 v1**（2026-10-31 讨论产出）。实现顺序见 §11，未定事项见 §10。
> 本文取代 `MEMORY-HANDOFF.md` 的讨论提纲，回答它提出的问题（对应表见文末）。
> 只写设计与契约，不含实现代码。

## 0. 一句话

每轮对话落一条 **turn 记录**（零延迟），攒够就整理成**合并记忆**；注入时从「合并层 + 最近几轮 turn」取，查阅时从 turn 层按相关度取、可下钻到原始聊天。

**每一层都是「骨架是事实、态度是她的」。**

---

## 1. 数据模型

### 1.1 两层 + 横向标签，不是一棵树

```
记忆系统
├── 合并层（有类型：事实 / 教训 / 关系 / 自我）   ← 一条合并记忆覆盖多条 turn
│        ↑ evidence（多对多，指向 turn 记录）
├── turn 层（无类型，只带主题标签）              ← 一轮一条（N=1），可拆成 1–3 条
│        ↑ 指针
└── 原始聊天（冻结；鱼自己存一份副本）
```

- **类型只在合并层。** turn 不带类型——一条 turn 同时是事实、是教训、是关系变化，硬归一类会丢信息。类型决定证据门槛与更新速率。
- **主题标签是横向多对多**，不构成层级。一条 turn 可以同时是「工作」「他对我能力失望」「周末」。
- **合并记忆不再合并。** 两层够了；三层会出现「她记得自己记得」，证据链变长且不可查。

### 1.2 turn 记录

时间上的「一轮」可能产出 1–3 条 turn 记录（拆分时），它们共享同一个原始聊天指针。

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| `id` | string | 系统 | |
| `scope` | `{ workspace?, session }` | 系统 | 她住在哪儿时发生的（换住处后仍有地理感） |
| `occurredAt` / `createdAt` | ts | 系统 | 一个真实 turn 两者相同；N>1 时才分开 |
| `raw` | `{ fromMsgId, toMsgId, chars:[from,to] }` | 系统 | 指向**鱼自己的**原文副本，不是宿主会话日志；`chars` 由中性的 `quote` 逐字定位得出 |
| `neutral` | `{ at, text }` | 中性总结 | **冻结**，写完不再变 |
| `her` | `[{ at, text, affect }]` | 她的总结 | **追加链**，可空（见 §2.5） |
| `affectAtWrite` | `{valence, arousal, guilt, longing}` | 系统 | 她写这条总结时的情绪 |
| `affectPeak` | 同上 | 系统 | 这一轮里情绪的峰值 |
| `tags` | string[] 0–3 | 模型 | 来自词表 |
| `hits` | `{ considered, used }` | 系统 | 两个计数分开，见 §5 |
| `summaryState` | `none \| her \| neutral \| both` | 系统 | 「还没想好怎么记」是合法状态 |
| `mergedInto` | memoryId[] | 系统 | 反查缓存，不是真相 |

### 1.3 合并记忆

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| `id` | string | 系统 | |
| `kind` | `fact \| lesson \| relation \| self` | 解析 | 决定证据门槛与更新速率 |
| `subject` | `user \| self \| between \| world` | 解析 | 这是谁的事；和 `kind` 是两个轴 |
| `claim` | string ≤80 字 | 模型 | 第三人称、可独立读懂、可检索 |
| `attitude` | string? ≤40 字 | 模型 | 第一人称，**可选** |
| `trigger` / `action` | string | 模型 | **仅 lesson**，分开存（检索要按 trigger 匹配） |
| `tags` | string[] 1–3 | 模型 | |
| `evidence` | turnId[] | 模型 | 必须是**本批真实存在**的 turn id |
| `evidenceStats` | `{turns, sessions, days, firstAt, lastAt}` | 系统 | 写入时算好，门槛判定不回查 |
| `counterexamples` | turnId[]? | 模型/系统 | 反例；没有它「被推翻」只是口号 |
| `affectPeak` | 同上 | 系统 | 构成它的 turn 里的峰值 |
| `affectAtWrite` | 同上 | 系统 | 合并那一刻她的情绪 |
| `confidence` | 0–1 | 系统+模型 | 初值由证据数定，后续可 `revise` |
| `reinforcements` | int | 系统 | 被**再次确认**的次数（不是被访问） |
| `createdAt` / `createdSeq` | ts / int | 系统 | 她什么时候想明白 |
| `firstAt` / `lastAt` | ts | 系统 | 覆盖的 turn 的时间范围 |
| `lastTouchedAt` | ts | 系统 | 最后一次被访问/被提及 |
| `hits` | `{ considered, used }` | 系统 | |
| `by` | `{ model, prompt, schema }` | 系统 | 溯源 |
| `sourceBatch` | `{ fromSeq, toSeq }` | 系统 | 幂等 + 审计 |
| `supersedes` | id? | 系统 | 「我以前以为是…现在知道…」 |
| `status` / `retireReason` | `active \| retired` / string? | 系统 | 退休 ≠ 删除 |

**两条互不干扰的版本轴：**

- **骨架链**：`claim` 不可原地改，只能新增一条并 `supersedes` 旧的，旧的 `retired` 但保留。
- **态度链**：`attitude` 永远追加，永远不退休。

混成一条线，以后就分不清「事实变了」还是「心情变了」。

**刻意不存的：**

- `weight`——它是 `confidence × f(reinforcements) × 时间衰减` 的投影，落盘会漂。能存的只是它的输入。
- 用户可编辑的内容——可见、可评论、不可改写（DESIGN §10.2）。这是立场，不是没做。
- 注入次数——那是宿主状态，不是记忆。

### 1.4 原始聊天

| 字段 | 说明 |
|---|---|
| `occurredAt` | 真实时间（不是总结时间） |
| `scope` | 同上 |
| `user` | 用户原话，一字不改 |
| `reply` | 鱼的回复原文 |
| `reasoning` | 回复对应的思考，**可选**，可能为空 |
| `model` | 生成这条回复的模型 |

**必须由鱼自己存副本。** 只指向宿主会话日志的话，会话一删、鱼一搬家，「原始」就断了。

### 1.5 存储形态

- 一条鱼一个目录，全部 append-only 的 ndjson：`log.ndjson`（事件）、`raw.ndjson`（原始聊天）。
- **不引入数据库。** 规模：一年约 9000 条 turn，几十 MB。真要换，触发条件是「同一只鱼需要多进程写」或「日志 > 50 MB」——那时数据库是索引，真相仍是 ndjson。
- 删掉任何投影缓存后，必须能逐位重算出同一结果。

## 2. 写入流程

### 2.1 时序

```
① 落原始聊天 + turn 记录          零 LLM，必然成功
② 评价（7 维）→ 更新 affect
③ 她的总结                        读 ② 之后的 affect；输出 used[]
④ 中性总结                        独立调用，与 ③ 互不读对方；产出拆分点与标签
⑤ 落记录                          按 segment 落成 1–3 条，共享同一原始指针
```

**① 必须先落盘。** 后三步任何一步失败都不丢数据，`summaryState` 记录到哪儿了，下轮补。这条是「一次 429 丢一轮」的直接解药。

### 2.2 三个契约

**她的总结**

```
输入：本轮对话原文 + 当时的情绪快照 + 本轮注入过的记忆 id 列表
输出：{ herSummary: string ≤120 字, used: string[] }
```

情绪**不在**输出里——情绪来自评价器，是确定性的。让她"说心情"只会得到一个不可比、不可衰减的说法。

**中性总结**

```
输入：本轮原文 + 上一轮最后一句（最小上下文；无情绪、无旧记忆、无人设）
输出：{ segments: [{ text ≤150 字, quote ≤40 字 }], tags: string[] }
```

- `segments` 同时承担**拆分**：一轮里有几件独立的事就产出几条，上限 3 条。每条带一句 `quote`——**必须能在原文里逐字定位**，系统据此算出 `raw.chars` 区间。定位不到的退回一条覆盖全轮。
- `tags` 由这次调用产出（它是「发生了什么」的那次调用，最有资格分类）；合并层的标签从 turn 继承、可再收窄。
- 「无上下文」要打个折：完全无上下文会写出「他问了那个东西」这种代词悬空的句子，三个月后连检索都检索不到。最小上下文就够。

**合并**

```
输入：一批 turn（每条含中性总结、她的态度、affectPeak、tags）
输出：{ memories: [{ kind, subject, claim, attitude?, tags[], evidence[turnId] }], supersedes?: id }
```

### 2.3 写合并记忆时，模型只填四个字段

`claim` / `evidence` / `tags` / `attitude`（可选）。其余全部系统算。

这不只是省 token，它是一道**免费的防幻觉闸**：`evidence` 必须是本批真实存在的 turn id，否则整条丢弃。旧实现存的是提示词里的行号，模型编了你也看不出来。

### 2.4 防幻觉的四条硬闸

1. `evidence ⊆` 本批 turn id，且 `ts(turn) ≤ ts(memory)`；
2. 证据数 ≥ 该 `kind` 的门槛，且**去重后**按 turn 计（`["1","1","1"]` 不算三条）；
3. `evidence.length ≤ 12`，超了必须拆，否则拒绝；
4. `quote` 必须能在原文里逐字定位——定位不到就说明模型在编，退回整轮一条。

第 4 条几乎免费，而且它拦的是最危险的一类错误：模型编造一段「他说过的话」，然后这条记忆被反复引用成事实。

### 2.5 失败与状态机

`summaryState` 从 `none` 开始，两次调用各自成功后推进。幂等键是 `(turnId, role: her|neutral)`——重复执行不重复落盘。

拆出多条记录时，它们共享同一个原始指针，`raw.chars` 各不相同。

## 3. 整理（合并层）

### 3.1 水位线，不是日期任务

```
已整理到 turn #N
```

- 整理 = 从 watermark 到最新，做完推进 watermark；
- 天然幂等、天然可恢复，断了从断点续；
- 待办退化成「有活要干」的标记，真正的位置在水位线。

日期任务（「今天需要整理」）会出三种毛病：漏一天产生两个重叠待办、补做时不知道做到哪、重复触发重复整理。

### 3.2 触发

- **上限触发**：未整理条数 ≥ `cap`（可配，默认 20，范围 5–100），标记有待办。
- **显著度触发**（待定，见 §10）：冲突、承诺、被否定、被夸这类轮次立即标记，不等 cap。否则「他今天跟我道歉了」要等 20 轮才被消化。

### 3.3 执行

- **只在空闲时做**，且必须有预算：一次空闲窗口最多处理 K 批。
- **必须分段**：攒了 500 条，一次调用装不下。按批（默认 20）推进，每批做完推一次 watermark。否则要么爆上下文，要么失败重来。
- **积压过多时降级成粗粒度**：按天合并，不再逐轮。

### 3.4 空闲整理的系统性偏差（必须修）

**如果所有合并都发生在平静的时候，她的长期记忆就全是「还好」。**

她整理旧账时情绪平静，写出来的「她怎么看」自然也是平静的。一个月后回忆那次争吵，记住的是「后来我们聊开了」，不是「当时我气得不行」。

两个修正：

1. 合并权重取构成 turn 的 `affectPeak`，**不取整理时的情绪**；
2. 合并提示词明确写「这是**当时**的感觉，不是你现在回头看的感觉」。

这也是 `affectPeak` 不能省的原因：它不只用于排序，它是「记忆的温度」的唯一来源。

### 3.5 门槛

| 类型 | 证据门槛 | 更新速率 | 上限 |
|---|---|---|---|
| 事实 / 偏好 | 2 条独立 turn | 1× | 可覆盖 |
| 教训 | 1 次成功即可 | 4×（最快） | 无 |
| 关系 | 3 条，且跨会话或跨天 | 0.5× | 有底线 |
| 自我 | 2 条，且跨场景 | 0.1× | 强封顶 |

「跨会话/跨天」用 `evidenceStats` 判定，写入时算好。

## 4. 召回

### 4.1 两条通道，两种排序

| 通道 | 触发 | 排序 | 取哪层 |
|---|---|---|---|
| **主动注入** | 每轮，不问问题 | 重要性（weight） | 合并层 + 最近几轮 turn |
| **查阅** | 「你还记得…」/ 她主动去翻 | **相关度**（BM25） | turn 层（含已退休），可下钻原文 |

把两者混成一条「按重要性往下翻」的队列是错的：找「他生日是哪天」这种只提过一次的事实，按重要性可能排在 200 条之后，得翻到底；按相关度一次命中。

### 4.2 分页 = 努力程度，不是检索算法

「第一批没找到就翻第二批、第三批」这个设计保留，但换个位置：它是**查阅时翻得多深**，判据是相关度不是重要性。翻得越深越像「她想了半天才想起来」——这个质感值得留。

### 4.3 检索分档

| 档 | 做法 | 何时 |
|---|---|---|
| L0 | 中文二元组 + 停用词 + 长度归一 + 命中门槛（≥2 个不同 token 或覆盖率 ≥1/3） | 先上 |
| L1 | 倒排索引 + BM25（k1=1.2, b=0.75），写入时增量更新 | 数据过千条后 |
| L2 | embedding + RRF 混合 | **已实现，默认关**（`memory.embeddings.enabled`）；开关由 `scripts/memory-eval.ts` 的结论决定 |

L2 的真正代价不是钱，是热路径多一个网络依赖。放行门槛：L1 的 recall@3 < 0.7 且误注入率已可接受。

评测脚本已经就位：

```powershell
node scripts/memory-eval.ts --fish <个体目录> --cases cases.json   # 标注用例
node scripts/memory-eval.ts --fish <个体目录>                      # 没有用例时用现有记忆自动生成自召回
node scripts/memory-eval.ts --fish <个体目录> --hybrid             # 开向量后对比
```

它输出 recall@1/3/5、MRR、top1 不是期望项的比例，并按「<70% 才值得上向量」给出结论。

### 4.4 扫描预算与诚实

「扫完全部历史才叫没有记录」不现实（O(N)，也和遗忘矛盾）。设扫描预算（默认 200 条 / 2 秒），超了就说「想不起来了」。

**「想不起来」本身就是一种行为**，比假装扫完好。

### 4.5 两层配比

默认「合并层 5 条 : 最近 turn 3 条」。合并层给结论，最近 turn 给即时上下文。

### 4.6 查阅通道的实现

「查阅」不是一个自动流程，而是给她一个工具：

```
memory_search(query, limit?)
```

- 她主动调用（想不起某件事、被问「你还记得…」时）；
- 返回合并记忆的结论 + 轮次的原话片段，找不到就如实说找不到；
- 命中的前三条记 `used`——翻出来真用上了，重量才会涨。

「联想」通道（每轮自动注入的那一句）仍然走同步的 BM25，不加网络依赖；工具走 `searchHybrid`，配了向量才会多一次调用。

## 5. 访问计数

### 5.1 两个计数

- `used`——她**真的用了**：回复里出现了这条记忆的实体或原话。
- `considered`——被判定「可能有用」但没真用上：弱信号。

只有 `used` 参与权重增长。被系统召回一次就 +1 的话，计数度量的是「系统选中它的次数」，不是「对她重要」——而且会自我强化：热门的更热。

### 5.2 判定时机

**放在「她的总结」那次调用里**，输出 `used: [id…]`。

- 不多一次调用（那次本来就要做，上下文里已经有注入的那几条）；
- 判据是「她真的用了」，且发生在回复写完之后——锚在结果上，不是自我评价；
- 配一条字面校验：`used` 里有、但回复里字面没出现的，降级成 `considered`。

单独发一次「判断哪条有用」的调用有两个问题：多一次成本；而且在注入后、回复前判断，那是**预测**有用，不是**实际**有用——预测永远偏乐观。

### 5.3 加一必须本地追加

不能等一次接口往返。它在一轮末尾，网络延迟会直接加进用户的等待里。

## 6. 注入渲染

### 6.1 骨架必出，态度可丢

```
事实：他真正在意的不是工具装不装得上，是被当成工具人
（我觉得这话我说得有点重）
```

一条记忆变两截，字数多 30% 左右。预算紧时先丢态度——**态度是加分项，骨架是记忆的本体**。不写这条规则，900 字预算会先被态度占满。

### 6.2 顺序与预算

预算按**字符**（默认 900，可配，下限 300）。前者先占：

| 序 | 块 | 上限 | 可丢 | 理由 |
|---|---|---|---|---|
| 1 | 名字 / 身份 | 1 行 | 否 | 她得知道自己是谁 |
| 2 | 未完成承诺（含 broken） | 2 条 | 否 | 违诺不消失 |
| 3 | 自我认知 | 2 条 | 否 | 被问人格时只许引这个 |
| 4 | 情绪 + 6 旋钮 | 2 行 | 否 | 情绪必须能改变行为 |
| 5 | 合并层记忆 | 配比内 | 是 | 骨架优先 |
| 6 | 最近几轮 turn | 配比内 | 是 | |
| 7 | 折叠 / 退休提示 | 1 行 | 是 | 「有些事记不清了」 |

### 6.3 同主题只出一条

按 token 集合相似度聚类，同一簇最多 1 条（阈值 0.35）。否则同义改写的几条会占满名额。

### 6.4 留在宿主的

何时 `inject()`、指纹比较、10 分钟内不重复、跨会话同步、声音规则、工具约束。渲染文本默认由记忆系统提供，宿主可覆盖模板，但**排序与预算由记忆系统定**。

## 7. 配置

| 常用 | 默认 | 范围/备注 |
|---|---|---|
| 每几轮记录一次（N） | 1 | 见 §7.2 |
| 整理阈值（cap） | 20 | 5–100；内部另有 token 上限 |
| 召回池（候选条数） | 20 | 必须 ≥ 注入条数 |
| 注入预算（字符） | 900 | 低于 300 只剩情绪、放不下记忆 |

| 高级 | 默认 | 备注 |
|---|---|---|
| 合并层 : 最近 turn 配比 | 5 : 3 | |
| 成长率 g | 1 | 四层速率联动的总滑块 |
| 主题标签词表 | 10–15 个 | 「其他」占比超 30% 时提示 |
| 平淡轮是否写她的总结 | 写 | 成本降级的第一级 |
| 中性总结 / 她的总结 的模型 | 待定 | 见 §10 |

### 7.1 三条纪律

1. **留痕**：改配置写一条 `config` 事件（键、旧值、新值、时间）。她应该能解释「为什么那阵子我什么都记不住」——那是你让我少记的。
2. **即时生效，只对新增触发，不追溯**：把 cap 从 500 调到 100，已攒的 800 条不会立刻触发八次整理；水位线按每批预算慢慢追。
3. **校验**：`cap ≥ N`；预算与召池自洽；非法组合直接拒绝保存而不是静默钳制。

### 7.2 这个旋钮改变的是「记忆粒度」

UI 上要写清楚：

> cap 越小，她越早把经历压成结论、留下的原话细节越少；越大，越晚总结，记得的原话越多但召回时更碎。

## 8. 不变量

| # | 不变量 | 怎么钉住 |
|---|---|---|
| 1 | 只追加 | 每次写入前后校验旧字节的 sha256 前缀不变 |
| 2 | 骨架不可原地改 | 只能在 `supersedes` 路径上新增；旧条 `retired` 保留 |
| 3 | 退休/折叠 ≠ 删除 | 不注入，但 `search()` 能返回，原文仍在 |
| 4 | 投影可重算 | 删缓存后 `weight` 逐位相同（1e-12），连删两次仍相同 |
| 5 | 证据可解析 | `evidence ⊆` 真实 turn id，`ts(turn) ≤ ts(memory)` |
| 6 | 证据独立 | 去重后按 turn 计；同一 turn 重复引用不算多条 |
| 7 | 失败不丢 | turn 先落盘；总结失败只影响 `summaryState`，下轮补 |
| 8 | 整理幂等 | 同一批重复执行，不重复产出记忆 |
| 9 | 计数不虚增 | 只有 `used` 参与权重；被召回本身不涨 |
| 10 | 温度不被平静改写 | 合并权重取 `affectPeak`，不取整理时刻的情绪 |
| 11 | 两层同源 | 同一只鱼的不同会话共享合并层与 turn 层 |
| 12 | 配置留痕 | 每次变更都有 `config` 事件，可回放 |

## 11. 实现顺序

1. **事件类型清单**——`turn` / `summary` / `revisit` / `merged` / `supersede` / `retire` / `revise` / `hit` / `config` / `consolidation-attempt`，全部 append-only。
2. **记录结构 + 校验器**（模型只填四个字段，四条防幻觉闸）。
3. **两个 LLM 的输入输出契约**，先用 mock 跑，不接真模型。
4. **渲染**（骨架优先、态度可丢、两层配比）。
5. **召回**（合并层取注入、turn 层取查阅）。

前两步是纯结构，可以完全不带模型先跑通——这样第 3 步接真模型时，出问题的只会是模型，不会是结构。

## 12. 实现注记（与本文的差异）

代码在 `packages/memory/`。落地时有四处按工程判断收了口，记在这里免得文档与实现对不上：

1. **没有 `seq`。** 水位线用「第几轮」的序号（turn 事件的顺序天然是稳定的，因为只追加），不引入额外的自增字段。§6.2 里 `seq` 的动机是「投影缓存别用数组长度当键」，那条对情绪缓存仍然成立，记忆侧用不上。
2. **拆分不落成多条记录。** 一个真实 turn 仍然是一条 `turn` 记录；中性总结把 `segments`（每段带原文区间）挂在 `summary` 事件上。检索按段落索引，注入与 UI 仍按轮次。这样「共享同一原始指针」不需要额外约定。
3. **总结是独立事件**（`summary` + `turnId`），不是 turn 上的字段。这样「总结晚到 / 失败重试」不需要改已经写下去的事件，§2.5 的状态机才成立。
4. **`tick` 每次最多 3 次调用**：两份总结 + 一次整理。一轮一次 tick，所以稳态下每轮 2 次、到点那次 3 次。

另外两处口径：

- `affectPeak` = 这一轮评价**之后**的情绪（先算出增量再落盘，等价于重放）。
- `reinforcements` 只被两件事推高：整理时模型又说了一遍同一件事（`revise`）、以及 `used` 命中。被注入本身（`considered`）不涨。

### 12.1 收尾项的实现口径

| 项 | 实现 | 口径 |
|---|---|---|
| 写锁 | `packages/memory/src/lock.ts`，每鱼一个 `.writer.lock` | 默认 `warn`：抢不到**照样写**（丢对话比双写更糟），但状态暴露给设置页告警；`strict` 才抛 |
| 冷启动 | `snapshot.json`，每 20 条事件写一次，`bytes` 匹配才用 | 只是缓存：删掉逐位重算，测试里钉了这条 |
| 向量 | `embed.ts`：可插 embedder + `vectors.ndjson` + RRF | **默认关**；失败/未配置一律退回 BM25，热路径不新增网络依赖 |
| 工具 | `memory_search`（`lib/memory-tool.js`） | 不 import `dsh-tools`，直接用注册表认的 JSON Schema 形状，保住零依赖 |
