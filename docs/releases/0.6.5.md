# 0.6.5

修「搬家后的房间没有标准工具 / 权限被卡住」。

## 为什么她会说"屋子是空的、我没法列目录"

我读了 `session-16860987…` 的对话。她的工具列表只有：

```
working_directory / memory_search / load_workspace_dependencies / fish_bili_look / fish_bili_speak
```

**没有 pwsh、read、glob**。所以她只能靠 `working_directory` 逐个猜目录名（`.dsh`、`notes`、`desktop`、`memory` 都试了一遍，全部不存在），最后只能回一句"屋子基本是空的，我手上没有能执行命令的东西"。

原因：我们用 `ctx.agents.create({ sessionId, meta: { cwd } })` 建会话，**没有挂标准 agent preset**。GUI 建会话时会 `agentPresets.resolve()` + `presets.mount(agentCtx, id)`，那一步才把标准工具装进 agent。我们漏了，所以新房间是个"没有手"的 agent。

## 为什么权限老被卡

两件事叠在一起：

1. 没有 preset → 工具根本没装
2. 新会话的审批策略是 `ask`，而无人值守的回合没有 answerer，需要审批的调用一律 fail closed

## 改了什么

- `createSession` 现在会：
  - `agentPresets.resolve()` 取默认 preset，在 `setup` 里 `presets.mount(agentCtx, id)`
  - `meta.agentPreset` 一并写入
- 建好后调用 `approval.setPolicy(agent, 'never')`：鱼是无人值守的，不该卡在"请确认"上（文件沙箱仍然生效）

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。**新建的房间**（和之后"换房间"产生的房间）会带标准工具、审批策略为 never。

小肥鱼现在这间（`session-16860987…`）是旧代码建的，仍然没有工具——给她"换房间"一次，新房间就正常了。
