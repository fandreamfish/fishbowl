# 0.10.3

两个问题，两个根因。

## 1. 总结一条都没有：appraiser 配置丢了

`~/.dsh/profiles/desktop/cordis.patch.yml` 里 **fishbowl 的配置整段不见了**（被 DSH 的设置页重写时冲掉了，只剩 ui 相关的条目）。于是插件用的是默认值：

```
appraiser.kind = 'scripted'   ← 关键词评价器
```

而双总结与合并只在 `kind === 'deepseek'` 时才跑，所以**一条总结都不会生成**，情绪评价也退化成关键词匹配。

已把配置补回去：

```yaml
- id: fishbowl
  config:
    appraiser:
      kind: deepseek
      apiKey: sk-…
    relation:
      kind: companion
```

## 2. 「问她今天做了什么，她回"我先眯一会儿"」

反编译事件顺序后看到的：

```
17:31:54 用户：你今天都做了什么
17:31:56 assistant：（正确回答：搬进来、摸文件夹、写日记、刷 B 站…）
17:31:56 状态块被作为 user/message 注入   ← 晚了
17:31:58 assistant：我先眯一会儿。有事叫我。   ← 她在回答状态块
```

状态块以「用户消息」注入，但注入时机落到第一步之后，于是被当成了一句新的话，她认真回了一句——看起来就像答非所问。

## 改了什么

状态块从"注入一条消息"改成 **agent 的动态系统提示段**（`fishbowl-state`，order 450）：

- 每次组装提示词时现算：情绪、倾向、记忆、承诺、许可、请求回音都在里面
- **不再产生任何 user 消息**，不会再被当成对话
- inbox 永远是空的，退出也不再提示"有任务在跑"

代价：系统提示每步都变，DeepSeek 的上下文缓存命中会差一些（之前讨论过，这次是必要的取舍）。

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0（e2e 改成校验动态段的内容）

## 升级

**要重启 DSH 本体**（不只是插件），因为 appraiser 配置在 profile patch 里。

重启后：她不会再自问自答；最多 10 分钟，积压的轮次会被总结成记忆。
