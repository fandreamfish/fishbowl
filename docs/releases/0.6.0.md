# 0.6.0

住处模型收口：**一条鱼一间房，终身唯一**。搬家不再是"换住处"，而是"归档旧房间 + 新建一间房"。

## 规则

- 建鱼**必须**选一个屋子，并在这个屋子里新建一间房
  - 屋子可以是现有的，也可以是新建的（目录选择器）
  - 不再支持"先不安排"、"住进别人的会话"
- 一间房只住一条鱼；**屋子本身不归任何鱼**，一个屋子可以住多条鱼
- 「整屋归某条鱼」取消（只保留旧数据的读取兼容）
- 搬家 = 归档旧房间 → 在新屋子建新房 → 搬入提示
- 归档：侧边栏隐藏、文件保留，可恢复；不会留下"新鱼看到旧对话"的问题

## 改了什么

- `being/tenancy.ts`：住处类型收口为会话级；冲突只剩"这间房有没有人住"；整屋只读兼容
- `app/housing.js`：只接受 `new-session`（现有屋子）与 `new-both`（新屋子+房间）
- `POST /fish`：没有 `housing` 直接 400
- `POST /fish/:id/move` 取代 `/occupy`：归档旧房间、建新房间、注入搬入提示
- 设置页：建鱼弹窗只剩两种去处；「搬家」弹窗改成"换房间"（只选新屋子，说明旧房归档）
- 清理空房间：默认**归档**（不再直接删文件），只有显式 `purge` 才删
- 会话列表过滤已归档的房间

## 兼容

- 现有两条鱼（大肥鱼、小肥鱼）都是会话级住处，不需要迁移
- 旧数据里的整屋住处仍能被读取，但界面上不再产生

## 验证

- 七套测试 exit=0（housing 测试按新语义重写，路由测试改为"没有屋子不能建鱼"）
