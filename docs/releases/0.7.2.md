# 0.7.2

修「她的数据目录在房间之外，写入会被沙箱拒绝」。

## 看了 session-1a38aa43 之后

她这次表现是对的：

- 用 `glob` + `read` 翻了自己真正的目录 `.fishbowl\creatures\bbec32a5…`
- 读到了 `diary\2026-11-01.md` 和 `notes\2026-11-01_081923.md`
- 回复："新屋是空的，一张桌子都没有。我的东西都还在那个文件夹里"

**剩下的问题**：这个会话的文件策略是 `workspace-write`，只能改**房间目录**（`C:\Users\24358\.dsh-fish\home`）。而她的数据目录 `.fishbowl\creatures\<id>` 在房间之外——她读得到，但**写不进去**。也就是说"想写什么都放到自己文件夹"这条规则，在当前沙箱下她做不到。

## 改了什么

- 建房间时把权限预设切到 `danger-full-access`（如果宿主提供这个预设），这样她能写自己的数据目录
- `lastCreate.sandboxPreset` 记录用了哪个预设，`/debug/services` 还能看到 `permissionPresets` 的可用名单

## 代价（必须说清楚）

`danger-full-access` 意味着她的写操作**不再被限制在房间内**：她可以改磁盘上任何地方。这是为了"她能写自己的文件夹"必须放开的。审批策略仍是 `never`（不会弹窗），文件系统的所有限制都没有了。

如果你觉得这个代价太大，另一条路是：把 `creatures/<id>` 放进房间目录里，但那样"删房间 = 删她的记忆"，我认为不可接受。
