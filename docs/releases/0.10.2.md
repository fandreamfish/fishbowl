# 0.10.2

修「新鱼一条总结都没有」。

## 为什么

代码本来就是**每轮各出一条**（中性 + 她那侧），但有两个坑：

1. **总结输出上限太低**：中性总结 `maxTokens: 500`、她那侧 `300`。新鱼的对话里有大量工具输出，转录很长，模型返回的 JSON 被截断 → 解析失败。
2. **失败两次就永久放弃**：`tries >= 2` 直接跳过，不重试。于是这两条鱼的每一轮都卡在"失败两次 → 再也不试"。

数据佐证：大肥鱼 3 轮 / 6 条总结、小肥鱼 37 轮 / 52 条，而 11-01 新建的两条（4 轮、13 轮）**总结数为 0**。

## 改了什么

- 中性总结上限 500 → **900**；她那侧 300 → **600**
- 失败重试改为**冷却 30 分钟**（不再是永久放弃）
- `tick` 的错误与拒绝现在写进 `trace.ndjson`（`memory tick:` / `memory sweep:`），以后不用猜

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。空闲清扫每 10 分钟跑一次，会把那两条鱼积压的轮次补上总结。

如果 10 分钟后仍是 0，`trace.ndjson` 里会出现 `memory tick: …`，把那几行发我——现在能直接看到是解析失败、限流还是模型名错误。
