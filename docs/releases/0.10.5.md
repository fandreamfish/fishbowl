# 0.10.5

修「一直未总结、0 条合并记忆」。

## 真因：预算被总结吃光，合并永远轮不到

`tick` 的顺序原来是：

1. 逐轮补总结（每轮 2 次调用，最多 `maxCalls`）
2. 最后才合并（1 次调用）

而每轮结束时的预算是 3、空闲清扫是 8。积压 5 轮就需要 10 次调用，预算在第一步就耗光了——**合并那一步从来没执行过**。于是：总结慢慢补、水位线不动、合并记忆永远是 0。

我用真实账本跑了一次探针，确认 LLM 与解析都没问题，纯粹是顺序问题。

## 改了什么

1. **合并提前**：先花 1 次调用把攒着的轮次整理成记忆，总结再用剩下的预算补
2. **预算提高**：每轮结束 / 空闲清扫 / 打开房间，都从 3、8 提到 **12**
3. **打开房间时补一轮**：进入她的房间就顺带补总结与合并，不必等下一次说话

## 实测（直接跑她的账本）

```
之前：14 轮，0 条总结，0 条记忆
之后：14 轮，14 条总结，3 条记忆
```

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。之后：

- 新的一轮结束后立刻有总结
- 积压 ≥ 3 轮且放了 10 分钟 → 自动整理成合并记忆
- 记忆详情里"待整理"应归零
