# 0.8.0

让「她的请求」真的有用。

## 为什么之前没用

两处断了：

1. **她的状态注入里没有请求**。`renderText` 只拼名字/情绪/倾向/记忆/承诺，从不包含 `requestDigest()`——答了也白答，她下一轮根本看不到。
2. **回答本身不触发任何事**。`answerRequest` 只是往账本写一条 `request-answered`，没有叫醒她，也没有任何机制。

所以你点「已同意」，效果就是记账本里多一行，她不知道、也不会去做。

## 改了什么

1. 状态注入里补上请求：

```
还在等回音: 你点头我再摸机器
他答过的: 你要想让我看看家当，得先给我开个口子。（同意）
```

2. 回答请求时会**叫醒她一次**：

```
（他回答了你的请求「你点头我再摸机器」：同意。想做什么就做，不想做也行。）
```

这是一次正常的对话回合——她会看到结果、决定做不做，也会写进记忆。代价是每次回答多一次模型调用。

## 请求仍然不是"权限开关"

它不会解锁任何工具——工具本来就都在。请求的语义是"她想做某件超出日常的事，先问你一声"；同意之后，她靠自己的判断去做，而不是靠一个硬开关。

如果你想要的是"没有同意就禁止某类操作"的硬门禁，那是另一个功能，需要给工具加 per-request 的许可表。要的话我再做。

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。之后点「同意」，她应该会接着做那件事，而不是毫无反应。
