# 0.10.1

修「记忆详情里没有总结」。

## 原因

总结（中性/她那一侧）是在**合并**这一步生成的，而合并原来只在一个条件下触发：

```
积压轮次 >= consolidateCap（默认 20）
```

截图里这条鱼只有 **4 轮**，离 20 差得远，所以一条总结都不会生成——界面如实显示"未总结"。

顺带发现：除小肥鱼（37 轮、合并过 3 条）外，其它鱼都是 0 合并、0 尝试。

## 改了什么

1. **积压也会整理**：积压 ≥ 3 轮、且最早那轮已经放了 10 分钟 → 直接合并（不必等满 20）
2. **空闲清扫**：插件每 10 分钟检查一次所有鱼，把攒着的轮次整理掉（每条鱼最多 8 次调用），这样不聊天时记忆也会长出来

## 成本

一次合并按"轮数 × 2 + 1"次调用（每轮两条总结 + 一次合并）。3 轮约 7 次小调用；20 轮则摊薄到每轮约 2 次。空闲清扫只在有积压时才会真正调用。

## 验证

- 新增测试：三轮积压十分钟后自动整理、水位线推进到 3
- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。最多 10 分钟后，她账本里那 4 轮会变成 1–2 条合并记忆，界面上的"未总结"会消失。
