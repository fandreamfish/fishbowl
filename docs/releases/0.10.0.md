# 0.10.0

导出 / 导入：把鱼搬到另一台电脑。

## 怎么用

设置页「养的鱼」列表底部新增：

- **导出** → 选一个目录 → 生成 `fishbowl-export-<时间>-<随机>/`
- **导入** → 选那个导出目录 → 自动恢复

## 导出包里有什么

```
fishbowl-export-…/
  manifest.json          # 版本、导出时间、每条鱼的 id/名字/出生时间
  creatures/<id>/
    meta.json            # 人格、出生时间、名字、住处
    log.ndjson           # 全部经历/记忆/情绪
    diary/ notes/        # 日记与小纸条
    config.json          # 这条鱼自己的设置
```

跳过的文件：`.writer.lock`、`projection.json`、`snapshot.json`（缓存，可重建）。

## 导入时做了什么

1. **动态创建** `%USERPROFILE%\.fishbowl` 与 `creatures` 目录（不存在就建）
2. 按 id 逐条导入：**已存在的鱼只补缺失文件**，不覆盖账本、不追加事件
3. 校验住处：如果 `meta.occupancy` 指向的会话在这台机器上不存在 → 清空
4. 创建/复用工作区 **「大肥鱼的屋子」**（`~/.fishbowl/home/大肥鱼的屋子`）
5. 把本次导入且**没有住处**的鱼各建一间房放进去（会话名 `<名字>的房间`），并注入搬入提示

## 幂等

重复导入同一个包：

- 鱼已存在 → 只补缺失文件，**不会重复追加事件**
- 房间已存在 → `skipped: 已有房间`，**不会再建一间**
- 工作区已存在 → 复用，不会新建

测试里覆盖了这一点：连续导入两次，第二次 `housed` 为空、会话数不变。

## 路径问题

- 账本/日记里的**历史**绝对路径不会改写（那是她当时的真实经历）
- 新的状态块每次都按当前机器计算数据目录，所以她会拿到新路径
- 换机器后旧会话不存在，旧房间会失效并重新分配——这就是第 3、5 步在做的

## 验证

- 新增导出/导入/幂等测试
- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件 + 刷新页面。
