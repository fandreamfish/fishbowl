# 0.14.2

修「切页后开关又关」。

## 真正的原因：不是没保存，是重载时读到了旧值

切页的瞬间发生两件事：

1. 组件卸载 → 我们补发保存（异步，还没写完）
2. 新页面挂载 → 立刻 GET `/fish/<id>` 读配置

GET 经常比 POST 先到，于是读到旧值把开关盖回去。看起来像"没保存"，其实几毫秒后文件已经写对了。

## 改法

- 加一层**乐观覆盖**：每次改动先把新值记进内存（按鱼 id），30 秒内有效
- 重载时如果本地有更新的值，就先用本地那份；等服务器值追上了再清掉
- 所有开关/输入改成**改的同时**就写内存 + 发请求，不再依赖防抖回调
  - 上网、说话：`set` / `setCm` 直接 commit
  - 作息：`setWake` / `setContact` / `setDiary` / `setAffect` 直接保存
  - 成长、来历：改动同步进 pending，切页 flush
  - 记忆：同上

## 服务端验证

直接调接口确认过：

```
POST {browse:{requirePermit:true}, comment:{requirePermit:true}}
→ resp  browse=True comment=True
→ GET   browse=True comment=True
```

落盘没问题，问题在客户端重载时序。

## 升级

重启插件 + **强制刷新页面**（Ctrl+F5）。旧的 client bundle 可能还在缓存里。
