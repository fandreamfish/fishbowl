# 0.7.4

修「另一个进程也在写这只鱼」的误报。

## 原因

写锁里记的是 `pid`，判断"还有人在写"靠 `process.kill(pid, 0)`。但 Windows 会**复用 pid**：旧的 DSH 进程退出后，同一个 pid 被 `conhost.exe` 拿到——于是"这个 pid 活着"被误判成"另一个写者还活着"。

你的锁文件里是 `pid: 26892`，我查了：

```
26892  conhost.exe  14:42:22
```

而真正在跑的 DSH 是 node 8904。锁是 14:29 写的，早就过期了。

## 改了什么

- 写锁增加**心跳**：持锁期间每 30 秒刷新一次 `at`
- 判定改为 **pid 存活 + 心跳新鲜度（2 分钟）**：
  - pid 活着但心跳过期 → 判为过期，可以接管，不再告警
  - 真正的双写（两个进程都在刷新）仍会告警
- `otherWriter` 改用同一套判定（不再各写一份）
- 新增测试：`pid 被系统复用（心跳过期）也能接管`

## 关于「14 轮待整理」

这个不是问题：合并是按批进行的，每批上限 20 轮。34 轮里已合并 20 轮（得到 3 条记忆），剩 14 轮等下一批。

## 验证

- 分层 / 接口 / 模块加载检查通过
- 七套测试 exit=0

## 升级

重启插件。旧的锁文件会在首次访问时被判过期并接管，警告会自动消失（不用手动删）。
