# 0.14.3

按独立审计（新 agent）修设置页的读写链路。

## 审计发现的硬问题（已修）

1. **`GET /fish/:id` 根本没实现**：路由只有 `/fish` 和 `/fish/<id>/...`，两段路径落到 404。设置页整页依赖它，所以“读取中/旧版本”不是后端没起，是接口不存在。已补。
2. **自动保存打到 `/fish/undefined/config`**：`client.js` 用了 `data.fish.id`，而 `/fish` 返回的 `fish` 是数组。作息、成长率、来历因此静默 404。已改成 `view.id`。
3. **回填读的是全局 config**：`load` 的 `useCallback(..., [])` 把初始 `view={level:'list'}` 闭包住，单鱼分支是死代码。已加 `[view.level, view.id]` 依赖，并改成请求 `/fish/:id`。
4. **来历（seed）读不出写不进**：`pickFishPatch` 不认识 seed，`fishConfigView` 不返回 seed。已补全链路（模板 / pick / merge / view）。
5. **section 浅合并会丢兄弟键**：只改 `comment.requirePermit` 会把 `comment` 其它 7 个键整段覆盖。已改成一层深合并；现有 5 条鱼已补齐（comment 9 键、browse 14 键）。
6. **状态/手动触发读全局**：`/fish/:id/browse`、`/fish/:id/bili`、手动刷一次、扫描回复都用全局 `cfg`。已改成 `configFor(cfg, c)`。
7. **清醒循环被全局开关一票否决**：全局关着时单鱼开不起来。已改成“只要有一条鱼开着就启动循环，逐鱼判断”。
8. **`comment.autoApprove` 是死键**：规范化不认它。已补。
9. **许可工具不看开关**：requirePermit 关着也会建申请。现在关着时直接回“这件事不用问，直接做就行”，不产生请求。

## 审计确认的事实

- 5 条鱼的 12 个顶层键齐全（growth/seed/wake/contact/selfTime/memory/browse/comment/capabilities/diary/affect/relation）
- 之前大肥鱼缺 7 个 comment 子键、小肥鱼缺 browse.requirePermit，都是浅合并造成的，现已补齐
