# 0.14.5

让写入自己补全：即使 config.json 已经被旧版本写残，下一次写入也会按模板补齐。

## 改动

- `writeFishConfig(stateDir, id, patch, cfg)` 支持传入 cfg：
  - 以 `fullFishConfig(cfg)` 为底，叠加旧文件，再叠加这次 patch
  - 旧文件缺 `comment.perDay` 之类的子键，会在写入时自动补回
- 配置路由与迁移都传入 cfg
- 现有 5 条鱼的 config.json 重新补齐：comment 9 键、browse 14 键、顶层 12 键

## 为什么需要

旧版本是浅合并：只改 `comment.requirePermit` 会把 `comment` 其余 8 个键整段覆盖。文件一旦被写残，新代码的"深合并"也补不回来（旧文件里就是没有）。现在每次写入都从模板打底，残缺状态会自愈。

## 验证

- 新增测试：把 config 写成只剩 `comment.requirePermit`，再写一次，断言 `comment.perDay` 等键被补回
- 分层 / 接口 / 导入检查通过
- 七套测试通过
