# 0.11.0

给她一个「可以随便动」的文件夹，别的地方只读。

## 结构

```
creatures/<id>/
  log.ndjson        账本      ← 她能看，不能改
  meta.json         身份      ← 她能看，不能改
  config.json       设置      ← 她能看，不能改
  home/             她的      ← 随便改
    diary/
    notes/
```

- 日记、小纸条从现在起写进 `home/`
- 老的 `creatures/<id>/diary`、`notes` 在启动时自动搬进 `home/`（幂等，空目录会删）
- 搬入提示与系统提示里的"你的家当都在 …"直接指向 `home/`，并写明"这个文件夹是你的，想写什么、存什么都放这里；别的地方可以看，但不要改"

## 写保护

在工具层加了闸：

- `write` / `edit` / `apply_patch`：目标路径不在 `home/` 内 → 拒绝
- `pwsh` / `bash`：识别 `Set-Content`、`New-Item`、`Remove-Item`、`Copy-Item`、`mkdir`、`rm`、`>` 等写操作，命令里出现 `home/` 之外的绝对路径 → 拒绝
- **读不受限制**：`Get-ChildItem`、`read`、`grep` 照旧

拒绝理由：

```
fishbowl: 只能改你自己的文件夹（…\home）；别的地方可以看，但不要改。
```

## 说清边界

这是**工具层**的限制，不是操作系统级沙箱。她能绕过的方式仍然存在（比如把路径拼成变量、调用别的写入口）。要绝对锁死，就得把她的会话改成 `workspace-write` 且工作目录设为 `home/`——那等于让她住进数据目录里，房间就不在你的工作区了。要不要走那一步，你定。
